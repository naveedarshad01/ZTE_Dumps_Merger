How the comparison works

Across sites matches a local ldn, then other local primary keys or moId. With normalization enabled, the suffix equal to ManagedElement in an ENB/GNB CUCP, CUUP or DU function root becomes {site}. Cell IDs, neighbor IDs and the rest of the path remain exact. This assumes equal local IDs represent comparable objects; hardware and neighbor IDs may have different meanings across sites. ManagedElement is treated as the site-level singleton. Same-site mode uses the complete primary key from row 5. No usable key and duplicate keys are reported without guessing.

Values are compared exactly, including letter case, spaces and stored cell types. (blank) is an existing empty value. Missing objects and sheets have explicit labels. Differences indicate variation; they do not establish that a configuration is wrong.

All configuration sheets are merged even when only a subset is audited. Empty sheets are preserved. Repeated source records are retained. Incompatible headers or unsupported data features block the merge with a specific reason.
